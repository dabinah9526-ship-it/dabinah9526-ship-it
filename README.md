<details>
<summary><code>P01</code> <b>K-STEP</b> — 한국 여행 SNS · 개인 프로젝트</summary>

<br>

한국 여행 사진과 장소, 이동 루트를 기록하고 공유하는 SNS입니다. 화면부터 API와 DB까지 혼자 연결해 보면서 SNS의 주요 흐름을 구현했습니다.

`2026.05.28 ~ 2026.06.08` · `1인 개발`  
`React` · `Node.js` · `Express` · `Oracle` · `JWT`

### 맡은 작업

- 서비스 기획과 Oracle DB 설계
- Express API 개발
- React 화면과 서버 연동
- 회원, 피드, 댓글, 팔로우, 스토리, 채팅, 알림 기능 구현

### 중요하게 구현한 부분

- JWT 인증과 bcrypt 비밀번호 암호화를 적용했습니다.
- 비공개 계정, 팔로우 여부, 차단 관계를 서버에서 다시 확인해 접근을 제한했습니다.
- 피드, 이미지, 여행 장소가 일부만 저장되지 않도록 같은 Oracle 커넥션에서 처리했습니다.
- 로그인한 사용자에 따라 좋아요와 저장 여부가 함께 내려오도록 API 응답을 구성했습니다.

<summary><code>P02</code> <b>UNIPET</b> — 반려동물 통합 플랫폼 · 팀 프로젝트</summary>

<br>

반려동물 쇼핑, 커뮤니티, 병원·미용실·호텔링 예약 기능을 제공하는 웹 서비스입니다. 5명이 함께 개발했고 저는 쇼핑몰과 커뮤니티를 맡았습니다.

`2026.04.09 ~ 2026.04.30` · `5인 팀 프로젝트`  
`Java` · `Spring Boot` · `MyBatis` · `MySQL` · `JSP` · `jQuery`

### 맡은 작업

- 상품 목록·상세, 장바구니, 찜, 상품평
- 게시글과 댓글 CRUD, 검색, 정렬, 페이징
- 공지사항, 비공개 글, 임시저장, 신고, 알림
- 금칙어 필터와 회원 권한 처리 개선

### 중요하게 구현한 부분

- 상품 조회부터 장바구니와 상품평까지 쇼핑몰 이용 흐름을 연결했습니다.
- 공백이나 특수문자로 금칙어 필터를 피하는 문제를 정규식으로 보완했습니다.
- 금칙어를 `BAD_WORD` 테이블에서 관리해 코드 수정 없이 추가·비활성화할 수 있게 바꿨습니다.
- 화면에서 버튼을 숨기는 것에 그치지 않고 서버에서도 작성자와 관리자 권한을 확인했습니다.

## 03 / TROUBLESHOOTING

문제 제목을 누르면 확인 과정과 수정 내용을 볼 수 있습니다.

<details>
<summary><code>FIX-01</code> <b>K-STEP</b> — 피드와 첨부 정보가 일부만 저장될 수 있는 문제</summary>

### 문제 상황

피드 하나를 등록할 때 기본 내용은 `FEED`, 이미지는 `FEED_IMAGE`, 여행 장소는 `ROUTE_SPOT`에 각각 저장됩니다. 저장 중간에 오류가 나면 피드만 남고 이미지나 장소가 빠질 수 있었습니다.

### 확인한 내용

세 저장 작업이 서로 다른 시점에 완료되면 하나의 피드에 필요한 데이터가 맞지 않게 됩니다. 각 SQL의 성공 여부보다 세 작업이 모두 성공했는지를 기준으로 처리해야 했습니다.

### 수정한 내용

세 작업이 같은 Oracle 커넥션을 사용하도록 묶었습니다. 모두 정상적으로 끝났을 때만 `commit`하고, 하나라도 실패하면 전체를 `rollback`했습니다. 사용한 커넥션은 `finally`에서 반환했습니다.

**결과**　피드와 첨부 정보가 함께 저장되거나 함께 취소되도록 처리했습니다.

</details>

<details>
<summary><code>FIX-02</code> <b>UNIPET</b> — 공백과 특수문자로 금칙어 필터를 피하는 문제</summary>

### 문제 상황

금칙어와 정확히 일치하는 표현만 차단돼서 글자 사이에 공백이나 특수문자를 넣으면 필터를 통과했습니다.

### 확인한 내용

띄어쓰기와 기호를 바꿔 여러 입력값을 테스트했고, 단순 문자열 비교로는 변형된 표현을 찾지 못하는 것을 확인했습니다.

### 수정한 내용

글자 사이의 공백과 특수문자까지 인식하도록 정규식을 적용했습니다. 게시글 제목·본문·댓글에서 같은 공통 메서드를 사용하도록 정리했고, 금칙어는 `BAD_WORD` 테이블에서 관리하도록 바꿨습니다.

**결과**　코드를 다시 수정하지 않아도 DB에서 금칙어 추가와 사용 여부를 관리할 수 있게 됐습니다.

</details>

<details>
<summary><code>FIX-03</code> <b>UNIPET</b> — 팀원 PC에서 상품 이미지가 보이지 않는 문제</summary>

### 문제 상황

제 PC에서는 보이던 상품 이미지가 다른 팀원의 실행 환경에서는 표시되지 않았습니다.

### 확인한 내용

화면마다 이미지 주소를 만드는 방식이 달랐고, 일부 경로가 특정 실행 환경을 기준으로 작성돼 있었습니다.

### 수정한 내용

DB에 저장하는 값과 화면에서 사용하는 이미지 경로 기준을 맞추고, 중복된 경로 조합 방식을 공통 기준으로 정리했습니다.

**결과**　팀원마다 실행 위치가 달라도 같은 이미지가 표시되도록 수정했습니다.

</details>

<details>
<summary><code>FIX-04</code> <b>따iT</b> — 타이머 버벅임과 시간 표시가 맞지 않는 문제</summary>

### 문제 상황

타이머가 동작하는 동안 화면이 자주 갱신돼 버벅였고, 내부 초 단위 값과 화면에 보이는 분·초가 맞지 않는 경우가 있었습니다.

### 확인한 내용

매초 전체 화면이 다시 그려지고 있었고, 시간 계산값과 표시용 문자열이 같은 흐름 안에서 처리되고 있었습니다.

### 수정한 내용

타이머가 표시되는 부분만 갱신하도록 범위를 줄였습니다. 내부 계산은 초 단위로 유지하고 화면에 보여줄 때만 시간 형식으로 변환했습니다. 종료 후에는 공부 기록과 누적 시간을 Firestore에 저장했습니다.

**결과**　불필요한 화면 갱신을 줄이고 시간 계산과 표시가 같은 값을 기준으로 움직이게 했습니다.

</details>
